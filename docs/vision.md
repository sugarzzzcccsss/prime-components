# 愿景与可检验主张

版本：0.1.0；编写日期：2026-10-26。本文是项目设计，不是实测结论。

## 保留的核心想法

未来机器人的价值可能更多来自可重用的组件、接口和组织方式。人形、轮式或专用形态都可以由部分共同组件构成；组件平台可以与这些整机路线共存。项目不以预言哪一种机器人会消失为前提。

每个主动模块应能够报告自己的身份、能力、健康状态及使用约束。用户提出的“各模块具有强大端侧算力”作为候选架构保留，同时与“基本模块具有本地控制能力，重计算由算力模块承担”的架构比较。后者可能减少成本和热负担，也可能增加依赖，不能预先宣布胜出。

组合首先可以由人手完成。手动快换、辅助装配、自动重构是三个不同阶段，不把接口统一等同于自组装已经实现。

## 怎样定义“素数”

先固定任务集合 T、任务分布、环境范围 E、任务质量 Q、资源预算 B 和允许的配置集合。模块型号集合 K 的每个型号还包含尺寸、连接面、额定负载、供电、通信、控制与计算能力等约束。

在这些条件下，寻找能够为每个目标任务提供合格配置的较小 K。应同时记录型号数、实例数、总成本、能耗、任务时长和恢复时间，得到权衡关系，避免把少型号当作唯一胜负条件。把所有功能塞进一个巨型模块能使型号数等于一，但可能摧毁维修和成本收益。

“删除任一型号都会使既定目标无法满足”只说明该集合不可再删；不证明它是全局最小。换一组任务、接口或性能限制，结果可能改变。所有候选型号仍待真实任务检验。

本版本的枚举器只是这个研究问题的局部工具：在给定小库存内为单任务选择功能覆盖组合。它不设计新型号、不联合优化任务全集，也不判断物理装配可行性。

## 三项假设与反证

| 假设 | 支持它需要什么 | 什么结果会削弱它 |
| --- | --- | --- |
| H1 模块复用降低全生命周期成本 | 同一批模块在至少三项冻结任务中达标，记录库存、装配、校准和维修成本 | 为通用性增加的成本、质量或效率损失超过复用收益 |
| H2 端侧协作有净计算收益 | 相同工作负载和精度下，实测吞吐、延迟和每任务能耗；包含通信与调度 | 加节点后端到端更慢、更耗能，或只有降低质量才加速 |
| H3 模块替换缩短停机 | 对照维修流程，记录从故障到首个合格任务完成的全程分布 | 发现、隔离、换件、标定和复验耗时抵消快换收益 |

## 算力目标的边界

“不亚于大型数据中心”需要指明比较对象、工作负载、模型版本、数值精度、批量、响应时限、节点数量、网络和墙上功耗，才能成为可检验命题。总 TOPS、总内存容量、单请求延迟、吞吐率和可用性不是同一个量。

独立任务分配通常比频繁同步的模型切分更容易受益，这是实验优先级判断，仍需测量。分散的内存不会自动变成一块低延迟共享内存，协议也不能制造带宽、能量或运算单元。联邦学习主要协调本地训练与更新，同样不等于随时可调用的统一算力池。

有限尺寸、供电、链路和散热使物理系统始终有扩展边界。项目追求可扩展性，并把扩展到何处开始失效作为需要公开的结果。
